## Architecture

![RAG Knowledge Assistant production architecture](docs/images/rag-architecture.svg)

The application deliberately keeps a credential-free baseline alongside the semantic production path. FastAPI routes local search through TF-IDF, while configured semantic requests use an embedding provider plus PostgreSQL/pgvector and feed top-k grounded passages into cited answer generation. OpenTelemetry instruments FastAPI and can export traces to an OTLP-compatible backend.

See [ARCHITECTURE.md](ARCHITECTURE.md) for the detailed design.

## Cross-project portfolio system

The repository now has an explicit interoperability boundary with the Agent Workflow Engine and AI Evaluation Harness.

```text
RAG Knowledge Assistant
  └─ answer + retrieved evidence
             ↓
      portfolio-evidence/v1
             ↓
Agent Workflow Engine
  └─ permission-scoped orchestration + runtime events
             ↓
      portfolio-evidence/v1
             ↓
AI Evaluation Harness
  └─ answer, retrieval, citation and tool-call metrics
```

`integration_contract.py` converts a grounded RAG result into a plain JSON-compatible record containing:

- query and output
- retrieved source IDs
- citations
- context passages
- retrieval ranks/scores
- optional latency
- optional tool-call metadata

The contract contains no credentials and does not require the downstream evaluator to import RAG implementation internals. Its builder and validator are exercised in CI.

## Run locally

```bash
python -m pip install -r requirements.txt
uvicorn api:app --reload
```

Open:

- Web UI: `http://127.0.0.1:8000/`
- OpenAPI docs: `http://127.0.0.1:8000/docs`
- Readiness: `http://127.0.0.1:8000/readiness`

Credential-free retrieval:

```bash
curl -X POST http://127.0.0.1:8000/search \
  -H "Content-Type: application/json" \
  -d '{"query":"How can AI agents reduce unsupported claims?","top_k":3}'
```

## Production-oriented stack

```bash
python -m pip install -r requirements-production.txt
docker compose up --build
```

This starts FastAPI with PostgreSQL 16 + pgvector and a local Jaeger tracing backend. The production retrieval path creates the vector extension/schema, persists chunks, and performs nearest-neighbor retrieval. Jaeger is available at `http://127.0.0.1:16686` for local trace inspection.

## Observability

OpenTelemetry can use the console exporter or an OTLP/HTTP backend:

```bash
OTEL_ENABLED=true
OTEL_SERVICE_NAME=rag-knowledge-assistant
OTEL_EXPORTER_OTLP_TRACES_ENDPOINT=http://localhost:4318/v1/traces
```

`docker compose up --build` configures that endpoint automatically against the included Jaeger service. GitHub Actions also starts Jaeger, sends a traced FastAPI request, and verifies that the service appears in Jaeger.

The bundled Jaeger configuration is an in-memory development/demo backend. Durable managed trace retention is an optional operational extension rather than a portfolio requirement.

## Security

Provider and database credentials are environment-based and never committed. Retrieved documents are explicitly treated as untrusted data rather than instructions. The answer-generation prompt rejects instruction overrides, secret requests, role changes, and tool/action requests found inside retrieved passages. These are defense-in-depth guardrails, not a claim that prompt injection is solved. See [SECURITY.md](SECURITY.md) for production controls and limitations.
